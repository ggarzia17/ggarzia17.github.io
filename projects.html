Guardian.ai - Blasterhacks 2025 Winner

March 2025

Guardian.ai is an emergency notification assistant that generates custom action plans for users based on their unique needs. It allows the user to create a bio that can include any information that would be needed in case of an emergency. Then Guardian.ai listens to multiple government hosted natural disaster APIs and analyzes the disaster to determine if it is a threat to the user. If Guardian.ai detects a threat it will then use the users bio to generate a custom action plan that takes into account any information they included in their bio. Guardian.ai will then notify the user via text and email that their is a potential disaster nearby and send them the action plan.

The LLM model we used was Llama 3-70b, which was hosted by Groq on their Language Processing Unit (LPU) AI inference technology. We utilized the increased speed to implement realtime feedback when the user was creating a bio. The LLM would notify the user about any information that could potentially be useful that they had not already added to their bio.

The frontend was created using Svelte and Tailwind. The backend was created using FastAPI and SQLite and was hosted on Docker. I worked with Brady Ancell and Matias Pena to build Guardian.ai

Trace Route

November 2024

This project was written in C++ using raw sockets to send network layer ICMP echo requests. The program sends packets with increasing TTLs until it receives a response from the device at the IP address provided to it or it has sent 30 packets total. The program also listens for replies to its packets and reads their headers to see what type of packet they are. If the reply is an Echo Reply then the program has reached its destination. If the reply is a TTL Exceeded packet then the program knows that that device is a step along the route to the destination. If the program does not receive a reply after a few seconds then it will timeout and send the next packet.

Clue

May 2024

This project was created as a group project with Brady Ancell for Software Engineering (CSCI306). The game was built with Java and the GUI was created using the Java Swing framework. The game implements all of the major rules of clue. One of the more interesting rules to code was moving a player when another player made a suggestion including them, and then updating their valid moves accordingly. For example if you end a turn in a room you are not allowed to guess there again unless you were moved there by another player. While implementing Clue we utilized Object Oriented Programming concepts such as polymorphism and the singleton pattern. In order to ensure quality of code, we implemented tests for all features using the JUnit framework.

Chess

December 2022

My Chess project was built as a final project for Foundational Programming Concepts and Design (CSCI200). The user interface built in the terminal and displays each sides captured pieces, the board, a move list, whose turn it is, and a prompt to enter the next move. Moves are entered by entering the square of the piece you are moving and then the square it is moving to (Algebraic notation was not added due to time constraints). Move validation is implemented and includes rules such as promotion, castling, 2 square first pawn moves, and check/checkmate detection. If an invalid move is entered it will tell the user that their move was invalid and prompt them to enter a new move.
